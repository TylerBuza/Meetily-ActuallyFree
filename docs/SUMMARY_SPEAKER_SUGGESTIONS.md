# AI summary speaker-name suggestions

Summaries has an opt-in, off-by-default **Suggest speaker names after AI summary** switch. Native `summary/speaker_names.rs` persists it in the installation data root. The summary service snapshots the switch into `SummaryCacheSource`; changing it invalidates reuse of English summary generation when translating. Older caches deserialize the additive flag as false.

When enabled, existing chunk/combine/final prompts request explicit, evidence-supported `Name (Speaker N)` pairs. A self-introduction or explicit source identification is required; mentioning a person or assigning them a task is not speaker identification. This adds no separate inference job. The existing native summary worker continues to own completion and cancellation.

`summary-speaker-names.ts` extracts standalone pairs, owner fields and table cells from the generated summary, using canonical English cached Markdown when available. Conflicting names for a channel are omitted. User-edited summaries are excluded. Enabling the switch can also display explicit pairs already present in an unedited summary. Turning it off hides suggestions. The option cannot establish real identity or force a model to supply names; absent, malformed or conflicting pairs leave the anonymous label unchanged.

The meeting transcript projects `Tony (Speaker 7)` with an **AI · unsaved** badge and **Save name** action. This projection changes neither stored transcript speaker labels nor text, timestamps, source channels, contacts, voice samples, exports or subsequent model inputs. Named speakers and the microphone's `You` provenance are preserved, including overlap components. Opening the naming dialog does not save anything. **Save AI name** invokes the existing explicit speaker rename operation, with its selected scope and original speaker identity. Only that acceptance persists a name and may trigger existing named-speaker/contact/profile behavior.

`useMeetingData` scopes summary state and completion setters to the meeting ID, preventing suggestions from a previous meeting on navigation. Frontend regressions cover parsing/conflicts, translated/edited summaries, raw-row preservation, persistence failure, unsaved review, explicit acceptance and stale completion. Native regressions cover prompt gating and cache invalidation. No model/audio fixture establishes naming accuracy: suggestions remain unverified text-based guesses requiring user review.
